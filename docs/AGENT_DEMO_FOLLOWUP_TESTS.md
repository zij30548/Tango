# 演示版复查：测了什么，还缺什么

2026-10-23。本轮按用户要求复查当前 Agent，不增加角色或框架，重点验证“已有流程是否可靠、失败是否真的被拦住”。最终数字与源码版本见 [本轮证据](agent-upgrade/demo-followup-verification.json)。

## 发现并修复了什么

新增边界测试首次19项中16通过、3失败。模型可以把“记住我喜欢粤语吗？”截成“记住我喜欢粤语”，使程序错误接受记忆提议；清空口味和截掉同句示范说明也有同类问题。

实际写入原本仍需用户确认，但提议权限也应正确。本次在原有校验器增加完整指令的疑问、条件及示范检查，检查来源的右边界，保守拒绝临时偏好变成长期记忆。不能再把“并不是”中的“并”当作独立动作分隔。

流程为：模型提出计划 → 程序核对完整原句与来源 → 拒绝越界提议 → 持久保存失败 → 同一消息再次查询不重新调用模型。补充了两条后台集成用例，确认失败尝试计数、不创建音乐任务、不自动重试。

这是授权边界修复，不能据此声称已经理解所有中文语义。

## 下一步按这个顺序做

1. **持久保存待确认提议与动作回执。** 当前音乐任务能恢复，未确认偏好及部分后续动作还在Qt内存中。应支持提议阶段退出后重新展示，保存后回执前断电也不重复写入或提前找歌。恢复展示不等于自动确认。
2. **冻结自由表达的新题并校准推荐质量。** 测纠正、指代、跨话题、超过6条历史及复杂组合，验最终动作和约束。听感由人工试听评分；已调试过的句子不能冒充独立新题。
3. **完善长期记忆的范围与删除。** 当前偏好为文本摘要，敏感属性过滤不是完备语义检测；清空当前口味也不会删除旧任务／路由快照。应做结构化音乐偏好、版本失效及明确的历史删除语义。
4. **补可查询的诊断和质量指标。** 先能按会话定位路由／任务／工具错误，统计失败、空结果、延迟和模型请求数，再决定是否需要管理页面或Monitor Agent。

MCP和动态多Agent仍在后续计划中。当前更有必要先补上述可恢复与可诊断能力；正式公开上线还需独立部署、备份恢复、用户隔离、额度并发和真实播放验收。

## 面试可以怎样说

“我把Agent的模型提案视为不可信输入，用完整指令授权、来源边界、任务版本和预算约束执行。新增对抗用例确实找出了模型截句绕过提议权限的问题，修复后再验证失败持久化和不重复调用；同时分开记录工程测试、真实模型效果与人工听感。”

- **为什么有确认还要校验提议？** 确认不能替模型错误理解背书，提议阶段就应拒绝越界。
- **测试全绿是不是准确率100%？** 不是，工程用例与独立用户任务的分母不同，模拟模型也不能证明真实语义表现。
- **为什么下一步先做动作恢复？** 它直接解决重启丢提议和重复执行风险，比先增加角色名更能改善当前体验。
