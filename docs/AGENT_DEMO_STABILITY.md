# 演示核心修复：做了什么、怎么验证

2026-10-24。已完成代码修复、工程验收及一次真实六任务复验，**真实结果仍有失败与未核验项**。简历可直接参考[精简材料](RESUME_TANGO.md)。

## 这一步的作用

先让已经提供的功能可靠衔接：单曲搜索／播放、歌手新作、数量时长修改、偏好确认、历史回顾、暂停恢复和采用。原真实首轮的失败仍保留在[原结果](AGENT_REPAIRED_QUALITY_RESULTS.md)，修复后不覆盖旧分数，也不能把已暴露题再次称为新题。

| 问题 | 原因 | 本次修改 |
| --- | --- | --- |
| 《松针雨》录音室版被当成错误歌名 | 歌名引号和引号外版本没有分别消费 | 独立完整语句解析，标题、版本和只读附句分开；未知附句不静默丢弃 |
| JSON合法但整轮被拒绝 | 提示说明与严格字段／动作契约不一致 | 同一份JSON Schema用于提示词和支持型号的HTTP结构化输出；执行前继续校验当前授权与任务版本 |
| “再查找”“只看搜索结果”等遗漏 | 受限表达覆盖不足 | 共享查询解析器与权限核验；新增自然前缀和完整只读修饰，保留否定／转述／条件反例 |
| 记住口味＋给一份歌单被当成纯偏好 | 完整编译漏“只做预览”，后备用途判断又漏名词式音乐请求 | 两处复用相同音乐请求规则；确认式偏好与独立找歌分别生成，不能为修复而绕过纯偏好保护 |
| 数量、历史和自然控制未正确续接 | 精确量词、历史问法及控制句型遗漏 | 独立总曲数解析；只读取本会话已路由艺人；控制动作绑定原taskId与revision |
| 拒绝后难定位结构问题 | 只有固定拒绝原因，缺字段差异 | 增加缺字段、额外字段、类型错误的计数，关联路由／消息ID；不记录原提案或未知键值 |

流程仍为：`保存当前消息 → 完整可解释的常见请求直接编译／其他表达交模型提案 → 同一权限与契约校验 → LangGraph音乐任务／只读回复／待确认提议／原任务控制 → 预览 → 用户明确采用 → 实际队列与回执`。

## 技术和代码

Python、FastAPI和LangGraph复用现有后台；Qt经原HTTP协议接入，没有增加第二套产品执行入口。

- [单曲解析](../backend_py/tango_backend/music_lookup_intent.py)、[发行解析](../backend_py/tango_backend/release_intent.py)：完整消费受支持表达，保留作品数据与执行授权的区别。
- [需求编译](../backend_py/tango_backend/request_understanding.py)、[数量约束](../backend_py/tango_backend/task_track_count.py)、[只读及控制句型](../backend_py/tango_backend/conversation_commands.py)。
- [统一输出契约](../backend_py/tango_backend/route_contract.py)、[模型传输](../backend_py/tango_backend/model_transport.py)、[正式校验](../backend_py/tango_backend/intent_routing.py)、[拒绝诊断](../backend_py/tango_backend/conversation_router.py)。
- [真实Qt工程回归](../backend_py/evaluation/demo_stability.py)与[执行入口](../scripts/check-demo-stability.py)：核对实际候选、任务、偏好、队列与后台回执。

结构化输出的型号与关键词依据[百炼官方说明](https://help.aliyun.com/en/model-studio/qwen-structured-output)。未知型号继续原JSON模式；已知型号只对路由请求发送Schema。结构约束不能保证来源、语义和权限正确；澄清与missingSlots对应关系等仍由正式校验检查。不为400、超时、截断自动降级重发，所有尝试继续计数。本次单次真实路由接口返回HTTP200、通过正式校验，正确提取25分钟；没有执行该辅助检查返回的动作，也不能据此声称总体意图准确率。

## 你今晚怎么用

项目根目录运行：

```bash
bash scripts/run-macos.sh
```

进入音乐助手，今晚优先演示：`记住我喜欢粤语，再推荐20分钟微醺歌单` → 等待预览 → `确认保存口味` → `查看我的口味` → `保留前三首` → `时长改成40分钟，其他不变` → `解释当前歌单` → `撤回修改` → `采用歌单`。这条主线已有本次真实观测。锁定入口目前支持固定前三，不能声称支持任意N。真实模型、网络或曲库不足时按实际错误与缺口解释，不能用旧预览代替本轮成功。

排查入口：`bash scripts/diagnose-agent.sh recent`，先复制真实会话／任务ID，再按[诊断例子](AGENT_DIAGNOSTICS.md)查看对应路由、工具、检查和调用账本；不要输入字面量“复制会话ID”。

## 面试怎么解释

**30秒：**我把模型输出当作待校验提案。完整可解释的常见音乐请求用受限编译减少格式失败，自由表达由千问生成同一类型的计划；两条路径共用来源、权限和任务版本检查。执行使用固定LangGraph图，预览、确认、采用和设备生效分开。我用真实Qt端到端检查候选ID、持久状态与回执，保留首次失败，将工程通过和真实语义质量分别报告。

1. **为什么有Schema还要业务校验？** 字段正确不代表用户授权、来源可信、旧任务版本仍有效；模型不能生成写入或播放权限。
2. **会不会规则越写越多？** 规则只接受完整有限表达，未知部分交受控模型或澄清，不截取一句话里方便执行的子串。共享解析器避免理解和授权各写一套。
3. **怎么证明修复有效？** 保留原失败，加同义表达及否定／条件反例，再检查实际桌面与持久事实；已暴露回归和未见语义题分开。
4. **现在是动态多Agent吗？** 是固定研究图与受控角色分工；真实MCP、动态Supervisor、在线Monitor和生产发布验收仍待完成。
