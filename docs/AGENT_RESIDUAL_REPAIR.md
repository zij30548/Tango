# 上轮为什么失败，残留怎么修

2026-10-24。用户要求解释上一轮根因并检查残留。本文是本次独立交付，原[修复报告](AGENT_E2E_REPAIR.md)与[真实新题成绩](AGENT_INDEPENDENT_E2E_EVALUATION.md)保留当时范围。

## 问题在哪里

请求经过“理解原话→校验权限→派发任务→保存回执→界面显示”。上轮问题跨越这些环节，增加模型角色或更换框架不能直接补上缺失的业务契约。

| 问题 | 根因 | 本次修改 |
| --- | --- | --- |
| 正常找歌被拒绝 | 只读附句没有完整解析；原P03“别放，先让我看看”与B01“也别记住什么”仍漏掉 | 对允许的修饰逐段验证，保留完整原话权限；未知附句不能被偷偷删除 |
| 记偏好报错，或误建歌单 | 有界解析与权限计算覆盖不一致；音乐任务缺少“当前只管理偏好”的互斥检查 | 共用偏好解析和来源计算，正确提议须确认；错误的music.task提案也要拒绝 |
| 新作查错歌手 | “我想知道”“给我看看”被当成歌手名一部分 | 只识别明确的有限查询前缀，保留歌手歧义守卫 |
| 复合记忆请求被当疑问拒绝 | 后续“发了什么”的词尾“么”触发整句记忆疑问限制 | 仅完整明确偏好命令加独立查询的词尾允许通过，真正疑问、问号和条件仍拒绝 |
| 明确拒绝仍显示结果未知 | 上轮只修会话路由层，任务HTTP错误的状态码与错误码仍被压成字符串 | 保存有限协议元数据，只有完整且可信的提交前拒绝才终结 |
| 恢复可能把其他动作当成功 | 普通任务恢复只查原requestId，未核验冻结动作、目标任务与版本 | 必须匹配原action、taskId、expectedRevision；缺证据保持未知，不能释放后续依赖 |
| 要求告知版本但聊天没显示 | 查找读取了version，聊天渲染只拼接专辑和时长，原断言也漏看版本 | 展示明确studio/live标签，缺失不推断；同时验最终聊天内容 |

原真实运行76次模型请求均返回，但业务仍失败；“HTTP返回了”不等于理解、权限和最终状态正确。22条正式路由拒绝中，有些原始提案字段并未保留，不能把全部拒绝都断言为程序误判。本次以可重复的具体原话和故障回执定位。

上轮10题/15交互的固定替身回归确实通过，但它漏掉了原24题中的部分原话和任务错误分支。因此先前“问题都已修好”的表述过宽，本次纠正覆盖说明，原分数不改写。

## 怎么修与为什么必要

1. 先把独立审查发现的失败保存，再修改产品代码，不只补一条成功示例。
2. 正确表达和错误模型提案同时测试：既要允许合法找歌，也要拒绝把记忆、条件、否定或引用变成执行权限。
3. 将确定拒绝与结果未知分开。幂等冲突、重放、5xx、超时、截断或缺证据不能据此认定未执行；unknown继续只读原ID，不自动重发。
4. 恢复核对原动作事实，不能用当前任务状态反推旧请求做过什么，不能覆盖新任务或跨账号状态。
5. 原生回归保留原十题，再追加原P03首句、原B01整句及偏好相邻表达；固定模型和合成曲库只验程序执行与最终状态。

技术栈保持 C++/Qt、Python/FastAPI/LangGraph、MySQL/Redis和本机SQLite，没有新增动态多Agent框架。

## 限制与后续

P03新增原生回归只覆盖第一句同名候选查找；“女声那个”的下一轮需要基于可核验候选事实的多轮消歧，不能因第一句通过声称全题通过。目前曲目类型也没有可靠的人声性别字段，不能从名字或未标Live推断。P10艺人发展时间线缺少资料来源和独立能力契约，仍未实现。真实模型自由表达、真实曲库和听感没有新增验收，不提供新版总体准确率。原新题B04缺夹具及其他未触达攻击的事实保持原样。

本轮不使用旧124次或历史额度，不上传配置、用户库和私有日志，不commit/push。生产部署、真实MCP、动态Supervisor、线上反馈告警仍分别待做。

## 面试怎么说

我发现Agent失败不只来自模型理解，还来自解析、权限和恢复状态的衔接。我先保留失败，再让合法表达与越权提案共用契约校验；客户端保留有限错误元数据，恢复必须核对原动作、目标和版本。回归核验最终候选与偏好状态，区分工程接线和真实模型质量，避免用替身通过率冒充准确率。

- 为什么不只优化提示词？程序仍要防止错误提案扩大权限，HTTP错误与幂等恢复也不由提示词保证。
- 超时为什么不重试？不知道是否已提交，换ID会导致重复动作；先查原回执和原动作事实。
- 测试全绿为什么仍有问题？通过结论有覆盖范围；增加原失败输入、邻近表达和反例，并保留旧成绩，才能发现漏测。
