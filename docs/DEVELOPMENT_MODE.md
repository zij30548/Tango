# 开发时直接测试 Agent

2026-10-20。现在从仓库双击启动或 VS Code F5，默认自动进入“本机开发测试”，不用注册、内测码或输入密码。这样可以反复测试对话，同时保留任务和数据的账号隔离。正式版仍使用正常登录。

## 怎么用

关闭旧客户端，双击 `run-macos.command`，或在 VS Code 按 F5。也可在项目根目录执行：

```sh
bash scripts/run-macos.sh
```

本机开发后台使用 `127.0.0.1:16383`，与原来的普通后台 `16382` 分开。启动器自动生成私有开发会话文件，不需要手动填写。首次编译需要等待；后台或依赖启动失败会明确报错，客户端也提供重试。

开发身份是新建的专用身份，重启后复用。它不会登录你的正式探歌账号或继承该账号的网易云授权；旧账号、历史和授权不会删除。需要会员播放时，在开发身份里自行连接网易云。

## 实际流程和技术

```text
双击 / F5 → 启动本机开发后台 → Qt 读取私有会话文件
 → 向受保护的本机开发入口申请两小时会话
 → 自动进入专用开发身份 → 正常发送对话、执行工具和保存任务
```

Qt/C++ 负责启动后的自动进入和失败重试；Python/FastAPI 检查开发开关、本机连接和私有能力令牌；MySQL 8.4 保存专用身份、正式会话和用量，SQLite 仅保留显式离线兼容模式。后续仍走 Python LangGraph 任务及服务端权限校验，语言和存储迁移未改变免登录的授权边界。模型配置位于私有 `backend_py/.env`，日志位于 `backend_py/.data/`。

开发身份初始额度为每天 10000 次、累计 100000 次模型尝试，使用量持续记录，不在重启时清零。普通账号的 30/300 默认额度不变；全站模型调用上限、并发和单任务预算继续生效。自动进入本身不调用模型、不创建或恢复执行任务，也不自动确认偏好或播放。

开发入口只在显式开发模式中启用，拒绝生产环境、外网绑定、浏览器来源和代理转发请求。会话文件为当前用户所有、权限 0600，放在已被 Git 忽略的 `.local/development/`，不打印令牌。该便利模式依赖本机和当前系统用户可信，不是公开游客服务。

## 需要验证正式登录时

```sh
MUSICPLAYER_DEVELOPMENT_MODE=0 bash scripts/run-macos.sh
```

该命令使用普通后台与内测登录。发布构建不启用开发环境变量，也不包含开发会话文件。直接运行 `uv run --project backend_py --frozen tango-backend` 默认关闭开发入口；远程后台默认使用正常登录。

## 验证与面试说明

首次 Node／PG 版本使用临时数据库、假模型和隔离 Qt 进程验证自动进入、身份隔离、额度不重置、异常重试以及正式登录保护，未消耗真实模型额度。详细结果见 [开发模式验证记录](development-mode-verification.json)。当前 Python＋MySQL 版本的迁移验证见 [MySQL 迁移说明](MYSQL_MIGRATION.md)。这些是工程验证，不是 Agent 推荐准确率。

最终后台完整回归 597/597，零失败、零跳过；Qt 客户端 27 项功能与窗口 4 项功能全部通过。另有 22 项配置／启动专项，与后台完整回归有重叠，不累加。窗口测试首次因测试自身查找了不存在的标签而崩溃，已保留日志并修正测试；重新验证通过，没有发现产品退出崩溃。

可以这样概括：我将开发便利与正式认证分开，通过受保护的本机引导入口换取普通短会话，保留现有账号权限和调用账本，避免为方便测试直接删除认证。

- 为什么不删掉所有认证？任务、记忆和用量依赖稳定用户 ID；删除后容易丢失数据归属。
- 怎么防止线上打开免登录？后台默认关闭，开发模式遇到生产环境或非本机绑定直接拒绝启动；客户端开关不能打开远程服务的入口。
- 为什么还有限额？免登录减少手动步骤，模型仍按实际调用收费；全站和单任务预算继续限制意外循环。
