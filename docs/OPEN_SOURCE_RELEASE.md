## 这一步解决什么

把当前 Qt＋Python/LangGraph＋MySQL/Redis 版本作为可阅读、可构建、可测试的源码发布。开源不等于已完成公网服务上线、安装包签名公证或推荐质量验收；当前能力和缺口继续见 [Agent 设计](AGENT_DESIGN.md)与 [能力清单](HARNESS_STATUS.json)。

旧私有仓库的历史提交包含用户数据库，所以新仓库从审核后的当前源码建立独立历史，不继承旧提交。原仓库保持私有，旧历史和未脱敏原始证据保留，不做强制推送或公开。

## 发布检查

1. 检查当前候选文件和旧 Git 历史，分别识别密钥、授权文件、用户库、日志及编译产物。

4. 对最终暂存源码再次扫描，并检查公开提交不含旧私有历史；先推送到新的私有仓库，核对后再公开。

## 面试怎么讲

我把桌面播放、后台会话与受控 Agent 编排分开，提供锁定依赖、分层测试和阶段证据。发布前同时检查源码与 Git 历史；发现历史用户库后保留原私有仓库，以干净历史公开新版，模型密钥和设备授权留在各自边界。

- **为什么 `.gitignore` 不够？** 它不会移除已经进入旧提交的文件，公开前还要核对可达历史。
- **为什么门禁通过还不能叫生产可用？** 离线契约通过与真实推荐质量、容量、运维及安装包分发是不同验收。
- **别人如何运行？** 按根目录 README 安装依赖，在本机配置模型服务；仓库没有共享账号或后台密钥。
