## 这一步改了什么

| 用户行为 | 原问题 | 本轮实现 |
| --- | --- | --- |
| 搜歌、指定版本播放 | 逗号、“先别放”等合法修饰也导致路由拒绝 | 完整解析歌手、曲名、版本与当前播放请求；只搜索不播放，明确版本要有证据且唯一匹配 |
| 推荐六首、保留前两首 | 两个数量共用retainFirst，首次找歌就要求保留不存在的曲目 | targetTrackCount表示总首数，retainFirst只锁现有前缀；数量、锁定、时长分别核验 |
| 保存、删除单项、清空口味 | 音乐词表和句式过窄，没有待确认提议 | 共享有界偏好操作解析；删单项按完整已存条目计算，显示变更后由本机确认 |
| 暂停、取消、恢复 | 自然语句被拒，原任务继续生成预览 | 识别完整控制表达并绑定原taskId/revision；等待回来不是自动恢复授权 |
| 歌手同名消歧 | 只能按数字选，作品指代未承接 | 从当前候选的受限身份线索唯一匹配；否定或歧义不猜ID，仍可明确选择 |
| 澄清和失败 | 后台question不进聊天；已知拒绝显示成未知 | 权威澄清持久进入消息；已知拒绝终结，传输未知只观察原请求 |
| 采用结果未知后再次打开 | 内存采用ID丢失，再次点击可能发新请求 | 派发前本机记录原ID；只读回执核对原动作和版本，缺证据不代替用户采用或自动播放 |

这些能力仍有明确语法和数据边界。未识别的复杂表达继续走受控模型或澄清，不声称任意自然语言都能正确理解。写偏好、采用播放与读取历史仍是不同动作。

## 流程、技术与代码

```text
当前输入 → 有界解析或一次模型提案 → 同一个类型/授权校验器
    → 查歌：设备唯一匹配及版本证据 → 只展示或当前明确播放
    → 偏好：提议 → 本机确认 → revision CAS写入
    → 音乐任务：独立总曲数/保留数 → LangGraph → 工具 → 最终约束检查
    → 控制：原任务和版本 → 暂停/取消/明确继续
    → 已知拒绝明确结束；结果未知只GET原ID
```

继续使用C++17/Qt5、Python/FastAPI/LangGraph、MySQL和Redis，没有更换AI框架或引入动态多Agent。可空的原操作事实与请求日志同事务保存；旧行不推断、不回填。SQLite仅用于设备日志或拥有者隔离回归，生产仍为MySQL。

- [路由与授权](../backend_py/tango_backend/intent_routing.py)、[偏好解析](../backend_py/tango_backend/request_understanding.py)：完整分句、有限修饰与当前授权共同校验，不能让模型截掉否定或条件。
- [曲数解析](../backend_py/tango_backend/task_track_count.py)、[任务契约](../backend_py/tango_backend/task_schema.py)、[时长选择](../backend_py/tango_backend/task_duration.py)：曲数与时长独立；固定首数时采用有界近似选择，不承诺全局最优。锁定超出目标先澄清，候选不足明确未满足。
- [任务运行时](../backend_py/tango_backend/task_runtime.py)、[任务存储](../backend_py/tango_backend/task_store.py)、[HTTP接口](../backend_py/tango_backend/app.py)：澄清持久化、原动作事实与只读回执；create夹带action字段不能冒充采用事实。
- [Qt会话](../conversationclient.cpp)、[本机派发与采用日志](../mainwindowradio.cpp)、[曲库工具](../musictaskclient.cpp)：已知拒绝/未知分开、版本与候选阈值、原采用ID持久恢复。

## 30–60秒面试概括

独立评测发现我的音乐Agent虽然工程测试通过，但真实自由表达会被授权守卫拒绝，曲数还和锁定数量混淆。我把总曲数、保留、版本和偏好操作做成明确契约，模型和规则共用校验。偏好必须本机确认，暂停取消绑定原任务，采用请求在派发前持久保存ID，未知只读取原回执。我再用真实Qt到FastAPI/LangGraph的隔离回归核对最终队列、偏好revision和任务状态，保留首次失败，并把固定替身的工程结果与真实模型语义效果分开。

1. **为什么不直接放宽校验？** 合法表达需要正确解析，但条件、否定、转述和未知版本仍不能授予播放或记忆权限。
2. **为什么采用要持久记录ID？** 响应丢失不等于没执行。原ID、动作和版本才能把查证与重发分开，防止重复采用；查证成功也不代替新的本机播放确认。
3. **怎样证明修复有效？** 对实际状态和权限反例做回归；真实模型效果要另冻结版本、用新授权运行，不能拿模拟结果编准确率。
