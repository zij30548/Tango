# 聊天工作区：气泡、清除会话和点击播放

2026-10-24。本阶段把音乐助手做成可直接操作的聊天界面，复用现有账号、路由和播放器。没有增加模型调用入口，也没有更改原真实评测成绩。

## 做了什么，为什么需要

| 用户操作 | 现在的行为 |
| --- | --- |
| 查看对话 | 用户在右侧，探歌在左侧；每条消息有边框、底色和留白。长消息换行，输入框固定在底部。 |
| 点击推荐歌曲 | 推荐区显示播放符号、歌名、歌手及已有版本资料；点击一首只播放这一首，不自动采用整张歌单。 |
| 清除全部对话 | 先确认，再清除当前探歌账号所有设备的服务端助手会话；当前设备同时清理该账号的待确认路由。重新打开不能恢复这些已清除的聊天。 |

这一步解决的是操作闭环：用户不用复制歌曲序号，也不用仅靠发送文字管理聊天。清除需要后台持久生效，不能只把屏幕上的消息隐藏。

## 三条流程

**显示对话：**持久消息 → 按角色生成左右气泡 → 将全部正文转义后展示。可见界面使用单个 `QTextBrowser` 文档，避免每条消息创建多个控件；旧 `QPlainTextEdit` 只作隐藏纯文本镜像，保留诊断和既有探针兼容。可见气泡另做几何、边框和点击测试，不以镜像替代 UI 验收。

**点击播放：**当前真实候选 → 程序生成内部歌曲链接 → 检查登录、配置、忙碌、歌手澄清和当前任务预览状态 → 发出原 `trackActivated(OnlineSong)` 信号 → 主窗口核验后解析播放地址并播放。链接映射绑定当前账号和候选版本；旧链接、正文伪造链接和外部网址不能取得播放权限。点击一首与“采用歌单”仍是两个操作。

**清除会话：**点击按钮 → 确认当前账号和范围 → 本机通过短时文件锁保存清除请求 ID → 废止旧异步回调 → 后台鉴权及账号锁 → 同一事务清空聊天、登记墓碑和幂等回执、清理可恢复路由内容并取消关联的未采用任务 → 收到可核验回执后清屏和清理本机待确认路由。

不同窗口共用本机目录时，文件锁只包读取、写入和删除，不跨网络等待；旧回执不能删除较新编号。其他窗口已核对并移除文件时，本窗口仍未知则继续重放原编号，不能新建清除误删后来聊天。

失败或结果未知时保留原消息及原请求 ID；再次点击核对同一次清除，不产生另一个可能误删新聊天的操作。确认期间切换账号会使原确认失效。清除期间不能提交新需求或点击推荐播放；原本正在播放的音乐继续。

## 保留什么，限制是什么

- 已保存音乐偏好、播放队列、曲库、采用事实、任务审计和调用额度保留；清除不会退还已经发生的模型尝试。
- 旧会话墓碑阻止迟到回复、恢复和新动作重新激活聊天。已经授权且等待设备回执的采用动作，只允许核对原采用 ID 的回执，不允许再次采用。
- 服务端范围覆盖当前账号所有设备；其他设备的本机缓存不会由此远程擦除，但重新读取不能取回已清除的会话。
- 这是聊天清除，不是全部个人数据物理删除。任务审计、备份和已有观测记录不在本按钮清理范围；生产数据保留与隐私删除仍需单独治理。
- 本阶段新增真实模型、网易云曲库及 Cloud 请求均为 **0**。固定上游和生成的 WAV 验证点击至播放器的链路，不证明真实推荐质量、整首歌曲播放或 VIP 权益。

## 你可以怎么验收

进入“音乐助手”后发送两条消息，确认自己在右、探歌在左；查询歌曲后直接点击推荐歌曲，检查底部播放器切到所选曲目。点击“清除全部对话”，先取消确认，消息应保留；再确认清除，重新进入助手，旧聊天不应恢复。已确认口味、队列和额度不应因此清空。

关闭旧 App 窗口后，在项目根目录运行 `bash scripts/run-macos.sh`；进入“音乐助手”即可。新的源码入口与操作无需配置额外模型 Key。

## 面试概括与追问

**30–60 秒：**我把聊天 UI 和 Agent 执行权限分开。用户点击的歌曲由当前候选映射到受控信号，模型正文和旧链接不能任意启动播放。清除聊天也不是简单清屏：客户端持久保存操作 ID，后台按账号加锁，事务写入墓碑和幂等回执，迟到路由不能复活旧会话，调用及任务审计继续保留。我用真实 Qt 窗口验证气泡位置和实际点击，再用隔离数据库测试并发、幂等及回滚，工程通过与真实模型质量分别报告。

1. **为什么清除需要墓碑和请求 ID？** 墓碑阻止迟到结果和旧入口恢复；请求 ID 让网络超时后的核对仍对应原操作，避免重复清除后来的新会话。
2. **为什么不能直接把模型返回的歌曲链接做成播放按钮？** 模型文本不提供播放授权。按钮必须映射当前账号、候选及版本，并经过现有权限与播放器校验。
3. **清除了聊天为什么还有审计？** 聊天体验清理与计费、任务证据和隐私物理删除是不同范围；必须向用户说明保留项，不能借删除聊天抹掉已发生的调用事实。
