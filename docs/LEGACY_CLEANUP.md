# 旧代码清理说明

日期：2026-10-21。

这一步把已经替换的 JavaScript AI 后台与配套历史执行工具移出当前代码树，让后续开发只围绕 Python 后台进行。原 Qt/C++ 桌面端、播放器和网易云适配服务继续使用；本次不是把整个 App 从头重写，也没有新增 MCP 或动态多 Agent。

## 当前保留什么

| 位置 | 当前用途 |
| --- | --- |
| 根目录 `.cpp/.h`、`tests/` | Qt/C++ 界面、播放、本机音乐工具与当前客户端测试 |
| [`backend_py/`](../backend_py/README.md) | FastAPI、Python LangGraph、账号、会话、路由、MySQL 任务状态与额度 |
| [`service/`](NETEASE_SERVICE.md) | 仍在使用的网易云 Node.js 适配服务；其 `.mjs` 不能一并删除 |
| `scripts/` 当前启动／构建脚本 | 准备 Python、数据库与网易云服务，启动和构建客户端 |
| `docs/evaluation-data/` | 原 `backend/evaluation/` 中的公开 JSON；只移动位置，保留原字节 |
| 历史评测 JSON／HTML、预算与源码清单 | 保留当时的成绩、失败、哈希和版本范围，不冒充当前效果 |

模型配置原字节迁到私有 `backend_py/.env`，权限为 `0600`，公开模板为 [`backend_py/.env.example`](../backend_py/.env.example)；新的日志与离线兼容目录为私有 `backend_py/.data/`。旧日志和旧后台 SQLite 文件在本机私有目录保留。当前账号与 Agent 数据继续使用已切换的 MySQL，客户端历史、收藏、偏好与网易云授权保持本机隔离。

## 哪些已退出当前版本

旧 `backend/` JavaScript AI 后台、依赖声明、配套 Node 评测／旧存储维护脚本、旧 Qt live probe 以及历史冻结目录中的源码副本，不再作为当前可执行入口。它们先归档到本机已被 Git 忽略的 `.local/legacy-cleanup/<本次ID>/source.tar.gz`，再从当前源码树移除；归档不包含真实密钥、Cookie、数据库和日志。

历史各版本的 `snapshot-manifest.json` 保留原位和原字节。清单里的旧路径表示当时测了哪些源码，源码现位于私有归档；清单本身不表示这些旧文件还在当前代码树，也不能独立代替可执行源码。需要复核旧版本时，先在隔离目录解压对应归档，不能覆盖当前工作区或连接真实用户库。

本次移除 644 个旧文件路径：旧后台 121 个、旧专属脚本 26 个、重复的历史源码 495 个、旧在线探针 2 个。另删除旧 `node_modules` 的 9696 个生成文件。8 份原始题集 JSON 移到 `docs/evaluation-data/`，7 份历史源码清单保留；661 份公开源码／脚本在删除前逐文件验证私有归档哈希。删除未加载的源码与依赖主要减少磁盘和维护负担，本次没有测量运行内存收益。

## 面试怎么说明

> 我把 AI 后台迁到 Python 后清理了旧 Node 运行入口和重复源码，保留必要的网易云 Node 适配器与 Qt 客户端。配置和私有数据按当前后台目录整理，历史评测保留版本与哈希，避免把旧结果当成新版本成绩。清理后重新验证启动、存储、接口和客户端贯通。

- **为什么不删掉所有 `.mjs`？** 网易云适配器仍被客户端使用，删除依据是运行依赖与功能归属，而不是文件后缀。
- **为什么保留历史报告？** 它们记录了真实失败、成绩和预算；保存证据不要求把旧后台继续放在当前运行目录。
- **这是不是整个产品重写？** 是核心 AI 后台迁移与工程升级；Qt 播放链路和网易云适配器继续复用。
