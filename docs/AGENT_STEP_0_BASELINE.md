# 第 0 步 基线 验收协议与面试说明

日期：2026-10-20。对应升级路线的第 0 步。当前功能代码来自 `bb6d0bc`，新增内容是验收工具和契约；统一会话、动态路由、MCP 与在线质量监测尚未接入。

本页记录第 0 步当时的 Node 基线。后续已完成第 1／2 步及 Python＋MySQL 迁移；旧 Node 执行器与源码已私有归档，当前运行和测试入口见 [Python 后台](../backend_py/README.md)，清理范围见 [清理说明](LEGACY_CLEANUP.md)。本页数字与冻结清单保持原版本范围。

## 这一步解决什么问题

以前“后台测试通过”“生成了歌单”“用户完成需求”容易混在一起。现在先固定代码、题目用途、统计分母和证据类型，后续每次改进都有可以复核的起点。

例如预选了三个任务，只得到一个成功结果，另外两个没有完成记录，完成率应为 1/3，另外两个保持未核验。不能只统计有结果的一题并报告 100%。这一规则已有可执行汇总函数和反作弊测试。

## 实际流程

```text
界定源码与私密数据边界
  → 固定开发验收场景与指标定义
  → 校验契约、统计器和隐私白名单
  → 跑隔离后台、适配器及 Qt 回归
  → 保留失败并做有明确假设的诊断
  → 生成 SHA-256 基线并复核文件变化
  → 输出工程结果，单列尚未开展的效果评测
```

冻结清单只读取明确范围内的代码、依赖锁文件、测试与公开评测资料，排除 `.env`、用户库、Cookie、缓存、构建产物及历史源码归档。源文件或目录符号链接、硬链接别名会被拒绝；重复冻结不能覆盖原文件。

九类质量事件包括：消息持久确认、路由、工具、检索、记忆、约束、任务终态、反馈和模型调用。事件不接收原始对话、凭据或任意异常文本；区分未执行、失败、未知和成功。模型调用即使失败或结果不确定，也不能漏记预算；缺少 Token 或费用时使用未知值，不能填成免费。

## 如何复核

本轮原始命令与日志位置保存在 [第 0 步记录](agent-upgrade/step0-verification.json)，对应执行器已随旧 Node 源码归档；不应在当前 Python 源码树照抄运行。冻结清单中的旧路径与哈希继续描述当时字节，不通过改路径、改分数或覆盖基线来消除版本差异。

当前 Python 工程回归使用 [后台验证命令](../backend_py/README.md#验证)；真实模型效果另按新的冻结协议和授权预算执行。新的测试通过不能替换本页历史结果。

Qt 的逐目标构建、sandbox 策略、清洁环境与执行命令在机器记录中。再次执行必须创建新的临时目录，禁止外网、真实用户缓存和生产数据；模型和曲库均使用测试自建的环回服务。原始日志与构建产物保存在记录中的 `/tmp` 路径，不提交用户日志或私密状态；机器记录保存哈希以供复核。

## 面试怎么讲

30–60 秒概括：

> 我在音乐 Agent 升级前先建立了基线和分层验收。代码与契约按文件哈希冻结，工程回归、开发场景和最终独立题分开。统计器把全部预选任务作为分母，保留失败、中断与未知，并拒绝重复结果和混合模式。我还定义了质量事件契约，明确区分工具执行成功、预览、采用与播放。这一步验证的是后续改造可以被可靠测量，实际推荐效果需要另外的真实模型与用户证据。

四个追问：

1. **为什么有 Git 版本还需要文件哈希？** 工作区可能有未提交代码、提示词、题目或评分器。提交号说明历史起点，文件清单说明实际测了哪些字节；两者一起记录。
2. **为什么工程测试不能证明 Agent 准确率？** 它们多使用确定性模型和曲库，证明协议、状态与失败保护；真实意图、召回、事实和听感需要对应数据与判据。
3. **为什么缺结果也留在分母？** 只统计成功返回的样本会产生幸存者偏差。缺失结果是未核验，不计成功；同时保留任务归因与模式。
4. **为什么允许诊断后再测？** 先保留失败，提出可检验假设，只改变一个因素确认原因，再明确执行修正环境验收。它不覆盖原结果，也不从多次结果里挑最好值。
