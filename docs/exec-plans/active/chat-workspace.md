# 聊天工作区：左右气泡、清除对话与单击播放

2026-10-24。用户要求实际完成三个界面功能，当前已完成本阶段工程验收和交付。前项[演示稳定性](demo-stability.md)的真实成绩与剩余额度独立保留，本阶段不使用旧预算。

## 验收与实现

1. 真实 Qt 页面使用可见 `QTextBrowser` 展示有背景和边框的聊天气泡，用户靠右、助手靠左；隐藏纯文本镜像仅供原诊断兼容。检查实际文档框的左右位置和背景，不只断言文本存在。
2. 推荐歌曲通过内部受控链接映射当前候选对象，单击仅播放这一首，复用原播放权益校验；不采用整张预览。旧链接、忙碌、切账号及清除期间不得触发播放。
3. 清除按钮先确认，默认取消；按当前探歌账号清除所有设备的持久聊天。后台事务墓碑阻止迟到消息和旧任务恢复，清除回执支持同 ID 重放。客户端先持久保存操作编号，结果未知时保留历史，只允许显式核对原操作。
4. 当前账号本机路由待确认记录随成功回执清理；已保存偏好、播放队列、调用额度及任务审计保留。清聊天不是个人数据或所有备份的物理删除，其他设备已显示的缓存不由本次实时推送擦除。

## 五类边界

- 上下文：清除后新聊天不引用旧对话与候选；长期偏好独立管理。
- 权限：账号所属校验、确认框期间账号不变、链接来自当前曲库对象，模型文本不能伪造播放权限。
- 执行：账号行锁、墓碑、原操作 ID、CAS/租约失效和未知不重发；原采用回执只补事实，不重复执行。
- 评测：离线 Python/Node、独立 MySQL/Redis、Qt 桌面与生成 WAV 分开记录；首次失败保留，不能算模型准确率。
- 恢复：未知清除操作编号跨客户端重启可读，原路由晚返回不能复活聊天；调用账本继续保留。
