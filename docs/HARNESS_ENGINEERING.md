# Tango Harness 工程规范

生效：2026-10-21。覆盖项目开发方法及音乐 Agent 的运行边界。五类是本项目按用户确认范围制定的分类，不声称业界有唯一的“五大原则”。

每次做功能，都要让助手**拿对上下文、只做获准的事、在边界内执行、用证据验收、出错能定位和恢复**。规范覆盖齐全，不代表当前产品能力全部完成；实际状态见 [能力清单](HARNESS_STATUS.json)。

自有代码新增或修改的说明性注释与文档字符串统一用中文，重点解释作用、原因和边界；技术名、代码标识符、工具指令与第三方许可原文保留。仅翻译注释时核验运行内容没有变化，不把语言整理当作功能改进。

## 开发流程

```text
读取进度和失败 → 明确一项需求与验收 → 检查五类受影响边界
  → 实现 → 自动检查与对应业务测试 → 审查与修复
  → 更新证据、缺口和进度 → 向用户解释
```

`AGENTS.md` 只做简短导航，详细规则、代码和证据留在仓库，复杂改动写 [执行计划](exec-plans/active/mcp-tools.md)。这种知识组织和机械化约束参考 [OpenAI Harness Engineering](https://openai.com/index/harness-engineering/)，不要求照搬其团队规模或工具。

长任务分步交付可运行状态、失败记录和下一步，避免只凭生成了代码宣布完成，参考 [长任务 Harness 实践](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)。用户对提交、付费和数据的授权优先，不因参考文章而自动 commit/push。

## 五类强制原则

| 原则 | 每次改动的要求 | 当前基础 | 待补能力 |
| --- | --- | --- | --- |
| 上下文与记忆 | 本轮要求优先；区分来源、限定规模；约束不因压缩丢失；记忆有范围、确认和删除语义 | 持久会话、受限历史、结构化任务、本机确认偏好 | Token 预算、相关记忆、压缩保真、派生失效 |
| 工具与权限 | 白名单、契约、账号/设备/版本/租约；工具内容是数据；后台模型和数据库密钥不进客户端 | 类型化路由、两类本机曲库 Skill、结果校验及确认 | 真实 MCP、统一执行器、来源治理、注入评测 |
| 执行与状态 | 超时、预算、停止、取消、幂等；先保存尝试再付费；未知不重发 | 固定 LangGraph、有界补查、事务额度、CAS/租约 | 动态 Supervisor、按需专业分工、无进展终止 |
| 评测与反馈 | 冻结版本、题目和判据；验最终状态；保留失败；对比效果、成本和延迟 | 工程回归、故障注入、真实Qt新题执行链及限定成绩 | 新题人工语义校准、攻击真实暴露、业务缺口修复及同条件对照 |
| 可观测性与恢复 | 关联消息、路由、任务、工具、调用和错误；脱敏；恢复不越权、不自动重发付费请求，未知尝试仍计数 | 账本、受限 trace、SSE、只读恢复、缓存降级 | 统一关联事件、退化计数、指标告警、反馈闭环 |

每类都在 [HARNESS_STATUS.json](HARNESS_STATUS.json) 登记“实现→测试→证据→缺口”。新增能力或改变边界时同步更新。`complete` 需要行为测试和证据且无该项已知缺口；文件存在不代表完成，清单合法也不替代执行测试。

### 上下文与记忆

- 当前路由取最近 6 条用户消息及受限任务投影，不是完整的 6 轮双向对话；任务规划另取受限消息。
- 长期偏好目前是本机账号空间的有限摘要与条目，写入须当前确认。“这次喝酒”不能自动变成永久爱好。
- 压缩/检索必须测纠正、否定、指代、跨话题、超预算及删除后不再召回。清空偏好不等于历史聊天、任务、路由快照已彻底删除。

### 工具与权限

- 程序计算不必成为 Agent；注册元数据不等于通用执行器；安装 MCP SDK 不等于实际联通。
- 模型提案经过程序校验。曲库标题、标签或网页文本不能修改权限、预算或确认要求。
- LangSmith 观测 HTTP 只在 `agent_tracing.py`，与模型传输分开；只发送受控摘要，不能借观测适配调用模型、修改预算或上传原始图状态。
- 后台校验设备提交结果的结构、版本与租约，但目前不独立认证每个曲目字段的上游来源。MCP 阶段须验证端点、身份和来源边界。
- 新适配登记端点、凭据归属、超时、取消、大小和错误语义。模型 HTTP 集中 `model_transport.py`，不得另建绕过预算的模型客户端。

### 执行与状态

- 保留每轮、每任务、全站及账号预算。失败与未知请求计入已预留尝试；数据库事务不跨模型网络请求。
- 读取历史不执行工具，重启不重发未知付费请求。重试须说明错误类别、原幂等 ID、剩余预算及停止条件。
- 新分支验证并发、旧 owner/revision、取消后迟到结果、心跳丢失、崩溃和重复回执。
- 预览、用户采用、队列生效是不同状态；偏好确认也是独立写入。模型自述不算实际完成。

### 评测与反馈

- 先写验收与对照，再测效果。工程断言、用户任务、轮次及调用分别计数；失败、未知和预算中断不能从分母消失。
- 新报告记录源码/模型/环境、题集与判据、命令、通过/失败/跳过、调用成本和局限。旧报告原字节保留，不挪作新版本成绩。
- 开发题、修复回归、独立题分开；人工或模型判定需要校准。参考 [Agent 评测实践](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)，本项目判断应落到音乐任务的最终证据和状态。
- 真实模型、曲库和听感分别验收。独立新题首轮76/200次，自动契约7/24，仍有2失败、12证据不足、3阻塞；见 [本轮阶段](AGENT_INDEPENDENT_E2E_EVALUATION.md)。无新增预算时只用模拟上游；当前不提供新版总体语义完成率/准确率，不自动使用本轮余124次。

### 可观测性与恢复

- 诊断日志和质量事件只记必要、受限且可关联的元数据，不记 Key、Cookie、令牌、播放地址、完整聊天或内部模型推理。持久会话业务库保存用户消息，仍需账号隔离和删除治理。
- 后续事件覆盖接收、路由、派发、结果、检查点、确认、取消、错误与恢复。进度流不是完整监控或 Monitor Agent 上线证明。
- 可恢复失败保留检查点和明确状态；允许的缓存/通知降级需退化信号。授权、数据库或限流故障不得放行新请求或改用旧用户库。
- 线上问题形成“复现→定位→修复→回归→监测”，不能只在提示词里加一句不要再犯。

## 自动检查及验证层级

```bash
# 只做仓库结构检查，不读取私有配置、用户库或访问网络
python3 scripts/check-harness.py
# 隔离的逻辑、本机模拟接口和服务快速回归
python3 scripts/verify-harness.py --tier quick
# 数据库、并发和恢复：拥有者临时 MySQL/PG/Redis
python3 scripts/verify-harness.py --tier mysql
# 界面/音频：原生 macOS Qt、模拟上游、生成的静音 WAV
python3 scripts/verify-harness.py --tier native
```

先按 [后台说明](../backend_py/README.md)安装依赖。MySQL 层还需迁移源的 PG 工具；原生层需 macOS、Qt5 和 hiredis。缺少依赖必须失败，不能当作跳过后全通过。

结构检查验证五类清单、合法相对引用、导航、产品不导入测试、旧后台不恢复成入口、HTTP 导入范围及 Qt 后台凭据标识。它不是安全沙箱、完整秘密扫描、语义正确性证明或上线认证。

快速 CI 配置位于 `.github/workflows/harness.yml`，不接付费模型、真实曲库或用户库；未在云端执行只能说已配置。Linux 快速通过不能代表 MySQL、多实例或 macOS 音频通过。

统一入口保留每次独立结果，失败退出、不自动重跑；私有报告只保存命令、退出码、范围和时间。公开验收另审脱敏输出、源码哈希及失败，不复制数据库或私有配置。按变更影响选层级，未做的验证明确说明。

本轮 [执行证据](agent-upgrade/harness-verification.json) 分别记录快速层、MySQL、PG 兼容及原生 Qt 结果，并保留首次失败和修复。各层有重叠，不相加成总体准确率；真实模型与曲库调用均为零。

## 交付、下一步和面试

每完成一个阶段，单独保留交付文档，并登记到 [阶段索引](STAGE_DELIVERIES.md)：作用与必要性、实施步骤、技术栈、源码、实际测试与结果、局限、面试概括和追问。当前架构总览用于理解全貌，不能替代或删除本次重做的阶段学习记录；阶段测试仍保留当时版本范围。

交付先讲作用和必要性，再讲流程、技术栈、代码、验证、限制、下一步，并附简短面试回答。当前按用户顺序先修独立新题暴露的业务/覆盖缺口，再做反馈告警回归和生产验收；[第 3 步 MCP](exec-plans/active/mcp-tools.md)仍待实施。随主线补上下文预算与关联事件，再解决记忆失效和无进展终止；动态多 Agent 要用独立效果和开销对照证明收益。

概括：我把上下文、授权、执行状态、评测和恢复定义为工程契约，用仓库规范、缺口清单、结构检查、隔离测试及分层验收约束开发。模型提出行动，权限、预算、最终提交和完成判断由程序及证据控制。

- 为什么不只加提示词？提示词替代不了事务、权限、幂等和验收。
- 门禁绿就能上线吗？只证明已检查的范围，原生体验与真实效果要分别验收。
- 为什么允许 partial？暴露真实缺口，规范齐全和产品能力完成是两件事。
